# 三人连续协作与交付约定

## 基线、目录与责任

以公开仓库 `main` 的实际提交为共同基线，启动时在 [当前状态](CURRENT_STATUS.md) 记录 SHA。`science/` 是冻结的共享参考区，只引用，不覆盖。新成果按唯一职责写入：A 的 `work/a_science/`、B 的 `work/b_compute/`、C 的 `work/c_delivery/`。引用历史资料时记录仓库相对路径、版本、页码或图号。发现冻结内容有误，在 Issue 说明，并于各自工作目录留下修正版及依据。

| 角色 | 具体产物 | 交接对象 |
|---|---|---|
| A 科学依据与项目逻辑 | R2 修正与 R3 未完成事项对照；研究问题、机制边界和候选逻辑；官方规则和附件逐项验收表（要求、出处页、对应文件、缺口）；正式摘要、评审文字、科学正文；关键结论来源 | B 核对计算数字与候选口径；C 使用冻结文字制作正式材料 |
| B 计算证据与复现 | 当前 9098 化合物库来源、版本和实际计数口径；已有代码、依赖、许可、输入、参数、随机种子、实际命令与日志；结果、候选、图件索引及 SHA256；无法复现项的原因 | A 核对科学解释；C 取已核查数字和图件 |
| C 展示与交付 | 图件、图注及统一版式；中文 16:9 PPT、同版讲稿、正式格式文件；按 A 的规则验收表登记满足状态；公开工程包、README、依赖说明、文件清单和 SHA256 | A 核对科学表达，B 核对图件数字；交最终整合人 |

B 优先整理已有真实结果，不因时间要求重跑无必要的大规模计算。9098 是当前库口径，核查发现差异时说明。规划扩筛不写成已做；R2 修正和 R3 未完成工作分开标识。C 在上游证据未交齐时先做版式、清单和已核查部分，将缺口显式留待补齐，不填造结论。

## 连续工作阶段

1. **T0 认领与基线：** 确认 #1、#2、#3 的实际负责人，记录 `main` SHA。最终整合任务 #4 在文字冻结前认领。每人认领后 15 分钟内 push 首个可审阅的真实工作计划，包括输入、预计产物和缺口。
2. **证据交接：** A 交官方规则出处页、R2/R3 对照与科学边界；B 交 9098 库口径、已有计算结果和复现边界；C 列展示所需文字、图件与正式格式。缺证据的主张先标待核查。
3. **文字冻结：** A 提交来源核查后的科学正文和结论清单；B 核对计算数字，C 核对正式格式。冻结表示该版本可排版，后续更正以新提交记录。
4. **图文成稿：** C 用已交接的文字和图件完成 PPT、讲稿、正式材料与工程包；A 核科学表达，B 核图件数字。各自 PR 列实物和缺口。
5. **最终合并：** 待认领的整合负责人核对非作者审阅、合并后文件与 SHA256、公开范围和提交状态，再决定发布。赛事官网提交另凭真实回执登记。

每批成果完成后 **5 分钟内 push**。连续工作最长每 **30 分钟** push 一次可审阅进展，可以是查明的证据、缺口或定位记录；不为满足节奏编造结果。每次在对应 Issue 留提交链接、文件和下一步。

## 互审与止损

A 核 B 的科学解释；B 核 A 的计算数字及 C 的图件数值；C 核 A/B 的正式格式与可读性。A、B 共同核 C 的科学文字与数据。每个 PR 至少由一名非作者审阅，指出文件、依据和具体修正即可，不设置层层签批。最终整合人不因角色自动代替专业核查。

关键科学结论必须有证据。证据不足时缩小结论、标明待验证或暂不纳入本版，其他可交付内容继续推进。计算筛选和对接分数不写成已证实结合、激活、抑制、疗效或湿实验结果。官网回执取得前，赛事正式提交状态保持未确认。
