# C 工作区：展示、格式与交付包

领取 [Issue #3](https://github.com/JoyceLeo326/life-science-challenge-tmc1-2026/issues/3)，分支建议 `work/c-delivery`。

## 本次必须交付

1. `report/`：按 A 提供的官方要求排版的报告/评审材料，可编辑源文件及 PDF。
2. `presentation/`：PPT 可编辑源文件、PDF 预览和逐页讲稿。核对字号、图例、单位、图号、引用和投影可读性。
3. `submission_checklist.csv`：逐项对应 A 的规则验收表，写清实际文件、格式/页数或字数、负责人和当前状态。签章、音频与官网回执按真实状态记录。
4. `package/`：公开交付包、中文使用说明、版本变化说明和 SHA256 清单。引用 B 的依赖和运行入口，不重新编写第二套算法说明。
5. `visual_review.md`：逐页核对记录、已修复版式问题、仍需处理项目。PPT、报告与讲稿采用同一套数据和结论。

先读 [科研入口](../../science/README.md)。等待 A/B 交接期间可完成版式、材料清单和包结构。A 给科学文字，B 给数据与科研图；C 负责组合、表达和最终文件质量，涉及科学含义的改动交回 A/B 确认。

C 制作交付包不等于自动担任最终整合人。发布与正式提交由三人另行认领的整合角色负责。每批完成后 5 分钟内推送，二进制文件修改时注明页码或修改范围。
